# 弹唱六线谱图片识别（OMR）方案

目标：把常见中文"弹唱六线谱"图片（和弦图 + 六线谱(× 拨弦 / 品位数字 / 扫弦) + 节奏符干 + 简谱旋律 + 多段歌词 + 反复记号，见各吉他谱站点的导出图）**准确**转换为 AGR v2 标准谱（`Line.kind = .system`），并剔除水印、网址、二维码、广告、页码等非谱内容。

## 1. 为什么不是"纯 OCR"或"纯大模型"
- 通用 OCR 只认文字，不懂 × 落在哪根弦、符尾表示几分音符、简谱上下点是八度。
- 视觉大模型对密集的几何位置（第几根弦、第几拍）不稳定，99% 做不到，且成本高、要联网。
- 这类谱几乎都是**软件排版生成的矢量渲染图**（字体、线宽、间距高度规则），非常适合**确定性的版面几何算法**，规则错误可检测（每小节拍数、和弦与和弦图一致、六线等距）。

=> **混合方案**：确定性 OMR 引擎（主力，离线，纯 Swift，可在 Linux 测试）+ 文字 OCR（iOS Vision / 开发机 RapidOCR）+ 一致性校验 + 可选 AI 修正（用户配置 API Key，只处理校验报出的可疑处）。

## 2. 流水线（`Core/Sources/AGRCore/OMR/`）
输入：`GrayImage`（8-bit 灰度，宽高，像素数组；iOS 由 CGImage 转，Linux 由 PGM 读）+ `[OCRToken]`（已有类型）。
1. **预处理**：自适应二值化（Sauvola）、去倾斜（≤3°，水平线投影）、尺度归一（以六线谱线距为单位 `u`）。
2. **水印/非谱内容过滤**：浅灰/彩色半透明像素层剥离（灰度直方图双峰 + 颜色饱和度）、斜向大字、二维码（定位图案检测）、页眉页脚区域、URL/站名/"扫码"/"关注"等文字规则 + 位置（系统框外）+ 跨页重复。保留的非谱文字进入 `meta.credits`（如"制谱：xxx"）。
3. **版面分析**：检测六线谱（6 条等距长水平线）→ 系统（system）；每个系统向上找和弦图行/和弦名、向下找节奏符干区、简谱行、歌词行（1..N 段）。
4. **小节线与反复**：竖线（贯穿六线）、粗细双线、`|:` `:|` 点、房子（volta）括号。
5. **六线谱符号**：连通域 → 分类器（× / 0–24 数字 / H P S / 弧线 / 箭头）。× 与数字按 y 量化到弦号，按 x 聚类成"同时发音事件"。竖线连接多根弦 + 箭头 = 扫弦（方向）。
6. **节奏**：符干/符尾（beam 数 = 八分 1、十六分 2）、附点、休止 → 每个事件时值；小节内 x 顺序 + 时值累加得 beat；**校验小节拍数 = 拍号**，不等则标记。
7. **简谱行**：数字 0–7、上下加点（八度）、下划线（减时线：1 条 = 八分）、`-`（增时线）、附点、`#`/`b`、延音/圆滑线、括号（前奏旋律）。
8. **歌词**：OCR 文字行按 x 对齐到简谱音符（逐字估计 x），多段歌词按行序 → `MelodyNote.lyrics[verse]`。
9. **和弦**：和弦名 OCR（"D7(5)" 等原样保留 + 规范化解析）；和弦图网格读取（弦×品、开/闭弦 o/×、起始品位数字）→ `ChordMark.shape`；与和弦名交叉校验。
10. **页头**：标题（最大字号居中）、歌手、`1=C`（调）、拍号 `4/4`、Capo/变调夹、速度。
11. **组装**：`Score`（sections 默认按系统分组，若有"前奏/主歌/副歌"标注则据此分段），`Line.anchor` 指向原图区域（原图模式自动滚动继续可用），`OMRReport`（每个元素置信度 + 校验问题列表）。

## 3. 数据与评测
- **合成数据集**（`tools/omr-synth/`，Python + PIL，字体下载到工作区）：从 AGR v2 谱随机生成（和弦进行、× 型分解/扫弦节奏型、简谱旋律、1–3 段歌词），以多种"站点风格"渲染（字体、线宽、间距、和弦图样式、符干样式），叠加水印（斜向半透明站名、角标 logo、二维码、URL 页脚、页码）、JPEG 压缩、轻微缩放/模糊/旋转。真值 100% 准确、数量无限。
- **真实数据集**（`datasets/real/`）：从网上收集不同站点的弹唱六线谱图片，并由人工/子代理转写 GT JSON。当前入库快照包含 159 张图片、109 份 GT 及对应元数据，来源见 `images/catalog.json` 和 `incoming/**/manifest.json`。本次仅保存已有文件，尚未逐项核验图片与 GT 的对应关系；原始下载缓存和临时裁剪图不入库。
- **指标**（`OMRScoring`，Core）：逐类别 F1 与总体加权准确率：
  - 和弦（每小节名 + 位置）、和弦图指法
  - 六线谱事件（弦集合 + × / 品位 + 技巧 + beat 位置），扫弦方向
  - 节奏时值、小节拍数
  - 简谱音符（音级 + 八度 + 升降 + 时值 + 延音）
  - 歌词字符（按段，CER）
  - 页头字段；水印误留 / 误删
- **验收**：合成留出集总体 ≥ 99.5%；真实集总体 ≥ 99%（逐类别报告，不达标的类别如实列出）。确定性引擎单独 + 引擎+AI 修正 两列分别报告。

## 4. AI 辅助（可选）
- 设置页新增"AI 辅助识别"：Base URL（OpenAI 兼容，可填 DeepSeek / 其他）、模型名、API Key（存 Keychain）、是否发送图片（视觉模型）。
- 触发：仅当 `OMRReport` 有问题项（拍数不符、低置信度符号、未知和弦、歌词对齐冲突、疑似水印文字）时调用。
- 请求：结构化文本（问题项 + 周边上下文的 OMR 结果 + 相关 OCR 文本），可选附裁剪后的局部图；要求输出 **JSON patch 操作**（`set`/`insert`/`delete`，路径指向 `sections[i].lines[j].system.measures[k]...`），Core 校验后应用，并重新跑校验，修正后指标变差则回滚。
- 开发期用本地子代理模拟模型应答（记录为 fixtures），App 运行时调用用户配置的真实 API。
